# make-knowledge-cards

把一篇文章变成 5-8 张知识卡片：一个知识点一张卡，每张卡只有标题、核心知识、简明解释、例子或自测问题。

纯提示词 skill，不含脚本、不调外部服务，装进 skill 目录即可用。

## 1. 解决什么问题

读完一篇长文，合上就忘；让 AI 写摘要，拿回来的是"作者说了什么"，不是"我能拿走什么"；再让 AI 补几个例子，它顺手编了几个原文没有的数字。三个问题叠在一起，笔记越做越多，真正记住的没几条。

这个项目把"读"和"记"之间那一步固定成一套流程：

- **压缩成可复习的单位**——不是把原文缩写，而是切成一个个能单独拿走的知识点，一张卡只承载一个
- **只留值得记的**——按可迁移性、因果链、可执行性排序保留，铺垫、个人故事、广告、重复段落一律删掉
- **不许编造**——卡片里每个判断都要能在原文找到对应句；原文没有例子就改写自测问题，不硬编
- **数量诚实**——知识点不够就少给几张并说明，绝不为凑数拆句注水

## 2. 主要功能

| 功能 | 说明 |
| --- | --- |
| 文本拆卡 | 把文章拆成 5-8 张卡片，每张一个知识点 |
| 重要性筛选 | 按 5 级优先级保留（原理机制 > 因果链 > 可执行方法 > 反直觉结论 > 有数据支撑的观点） |
| 去重合并 | 同一知识点跨段重复则合并；并列条目按"抽掉一条其余是否成立"判断该分还是该合 |
| 数量自适应 | 目标 5-8 张；不足 5 个知识点时输出实际数量并说明；超过 8 个合并次要项并注明取舍；极短输入给 1-2 张 |
| 例子 / 自测二选一 | 原文有例子用原文例子（标注"原文例子"）；没有则写能用原文回答的自测问题 |
| 反编造约束 | 5 条红线：不加事实与数字、不把推断写成结论、解释不新增因果、不编例子、补充背景须显式标注 |
| 文体适配 | 科普、教程、清单、观点、访谈、代码密集、超长文七类各有处理策略 |
| 交付前自检 | 10 项清单逐条核对（单知识点、无重复、事实可溯源、标题具体、数量合规等） |
| 多文件 | 给多个 `.md` / `.txt` 时逐个处理，每份结果标注文件名 |

不支持的输入：网页抓取、PDF / 图片 / 扫描件、Anki / CSV / JSON 导出、图形界面排版。

## 3. 安装方法

skill 由两个文件组成，复制到任一 skill 目录即可，不需要安装依赖：

```bash
git clone https://github.com/chenchunhao350-glitch/article-to-knowledge-cards.git
cp -r article-to-knowledge-cards/skills/make-knowledge-cards ~/.workbuddy/skills/
```

两种作用域按需选：

| 作用域 | 路径 | 适用 |
| --- | --- | --- |
| 个人级 | `~/.workbuddy/skills/make-knowledge-cards/` | 所有项目都能用 |
| 项目级 | `<repo>/.workbuddy/skills/make-knowledge-cards/` | 跟仓库走，团队共享 |

装完重启会话，skill 才会被加载。验证是否装好：问一句"帮我做知识卡片"，能被正确触发即成功。

## 4. 使用方法

不需要记命令，用日常说法提需求，满足触发词就会调用：

```
帮我把这篇文章做成知识卡片
（粘贴正文）
```

```
把 notes/2026-cold-chain.md 拆成知识卡片
```

```
这几份 txt 都提炼一下知识点，每份单独输出
```

常见触发说法：`做成知识卡片`、`整理成卡片`、`提炼知识点`、`拆成卡片`、`帮我做学习卡片`、`这篇文章讲了什么重点`。

用法上有三点要知道：

- **长文直接粘贴**：skill 不抓网页，公众号、网页、PDF 请先拿到正文再粘进来
- **文件给路径即可**：支持 `.md` / `.txt`，多个文件逐个输出、各自标注文件名
- **默认一次交付**：不会中途反问，要调整数量或风格，在提问时一并说（例如"只要 5 张""多用例子少用问题"）

## 5. 输入输出案例

### 案例 A：粘贴文本

输入：

> 深睡主要发生在前半夜，负责身体修复和免疫调节；REM 多在后半夜，与记忆巩固相关。因此熬夜到凌晨再补觉，损失的深睡较少，但 REM 明显不足。咖啡因的半衰期约 5 小时，下午三点后摄入，到晚上十点体内仍残留约四分之一。

输出：

> 来源：粘贴文本｜卡片 3 张（原文有效知识点 3 个，未凑到 5 张）

### 卡片 1：深睡在前半夜，REM 在后半夜

**核心知识**：深睡集中在前半夜负责修复，REM 集中在后半夜负责记忆。

**简明解释**：两个阶段在夜间的分布不对称，所以"少睡前半段"和"少睡后半段"的代价不同。这也是判断"补觉能不能补回来"的依据。

**自测问题**：凌晨两点睡到中午十二点，睡眠时长够了，哪个阶段仍然会不足？

### 卡片 2：熬夜补觉补不回 REM

**核心知识**：熬夜到凌晨再补觉，损失的深睡较少，但 REM 明显不足。

**简明解释**：这是卡片 1 的直接推论——后半夜被压缩掉的正是 REM 密集区。补觉能延长总时长，但无法把错过的 REM 挪回原位。

**自测问题**：为什么"睡够 8 小时"不等于"睡得好"？

### 卡片 3：咖啡因半衰期约 5 小时

**核心知识**：咖啡因半衰期约 5 小时，下午三点后摄入会影响入睡。

**简明解释**：按 5 小时衰减，下午三点喝的咖啡到晚上十点仍残留约四分之一剂量，足以推迟入睡时间。

**自测问题**：计划晚上十一点睡，最后一杯咖啡最晚几点前喝完？

### 案例 B：本地文件（清单型长文）

输入：

```
把 notes/remote-collab.md 拆成知识卡片
```

输出（节选，10 条建议合并为 8 张）：

> 来源：remote-collab.md｜卡片 8 张（原文 10 条建议，合并 2 组后成 8 张）

### 卡片 1：会议要有议程也要有结论

**核心知识**：没有议程的会议不开，结束前明确谁在何时做什么。

**简明解释**：原文把这两件事分列在第 1 条和第 6 条，是同一件事的两端：进门没目标、出门没分工，会议都等于没开。

**自测问题**：一个会议有议程，但结束时没有分工，问题等同于哪种情况？

……

合并说明：第 1 条与第 6 条合并为卡片 1（会议的两端），第 3 条与第 9 条合并为卡片 3（同一沟通渠道的两条规范）；其余 6 条各自独立成卡。

### 边界行为

| 输入情形 | 输出行为 |
| --- | --- |
| 知识点只有 4 个 | 输出 4 张，开头注明"未凑到 5 张" |
| 知识点有 12 个 | 合并次要项封顶 8 张，结尾注明合并了哪些 |
| 极短文本（不足 200 字，单要点） | 输出 1-2 张，注明信息量有限 |
| 某条建议原文只有一句 | 解释写 1-2 句并注明"原文未展开"，不注水 |
| 原文没有例子 | 一律改写自测问题，不自行编造例子 |
| 空输入 / 路径不存在 | 停下说明问题，请用户补正文，不凭空续写 |
| 给的是 PDF、网页链接 | 说明不支持抓取，请先提供正文 |

## 卡片规范

| 字段 | 要求 |
| --- | --- |
| 标题 | ≤ 14 字，脱离上下文也能看懂 |
| 核心知识 | 一句陈述句，≤ 40 字，不得出现"并且/另外/同时" |
| 简明解释 | 1-4 句，讲清来由、条件或机制，不照抄原文，不新增因果 |
| 例子或自测问题 | 原文有例子用原文例子；否则写能用原文回答的自测问题 |

完整的 7 步工作流、去重策略、七类文体适配表、5 条反编造红线、10 项自检清单，见 [`skills/make-knowledge-cards/SKILL.md`](skills/make-knowledge-cards/SKILL.md)。
